## Preserve, Do Not Overclaim

`release_approval._project_identity` reopens a real directory, refuses all dirty/untracked
state, requires matching HEAD and protected main, checks actual pyproject identity/version
and hashes named release documents. `_candidate` binds the exact wheel/SBOM/provenance/
checksum set and validates gate metadata. `_hosted_release` fetches actual release-run and
job JSON, checks completed success, exact SHA/branch/workflow/repository/attempt and exact
required job names without missing/duplicated/truncated rows. `_attestations` snapshots
bound bytes and invokes gh attestation verification with source/signer SHA, official
workflow and denied self-hosted signing. `_verify_signature` uses real detached OpenSSH
owner verification on canonical bound approval bytes and configured allowed signers.

`verify_release_approval` reopens these artifacts/hosted facts rather than accepting a True
flag, checks exact template/manifest/instructions/commands, verifies the owner signature,
and returns authorized commands without executing them. Reuse its mechanisms where the
contracts actually match. It does not prove independent editor preference, Sorani accuracy,
complete frozen acceptance, a 30-day use journal or a fresh holdout. Its declared external
human-quality/rights residual risk must remain explicit.

`evaluate_editorial_study` recomputes inventory/selected media/manifest/packet, verifies
coordinator, two reviewers and adjudicator, enforces distinct identities/key fingerprints
and chronology, and preserves exact disagreement reasons. The returned dataclass is not
an unforgeable credential; reopen the signed bytes and configured trust, not just this
object or a report's status. Keys/names alone cannot verify reviewer independence or native
expertise. Current caller-supplied trust-file arguments are not a protected web authority.

The actual packet's A/B are incumbent/shadow JudgeVerdict title/description/hashtag labels
over one source interval. They are not separate rendered reel MP4s. `_freeze_study_items`
splits individual candidates per dialect and still overlaps source groups. `_parse_study`
enforces that exact old split policy/count. Merely calling the disjoint helper from one
place would conflict with this parser/evaluation recomputation and legacy data: version
the policy deliberately, preserve old records as unverified for release, and cover every
affected caller. Source IDs/speaker IDs and actual media digests are distinct requirements.

Preparation places the answer key and reviewer packet in one directory with instructions
to withhold the key. Evaluation publishes training and holdout labels together. These
instructions are not OS-private distribution or a sealed disclosure protocol. Adapt the
existing owner-private storage and exact-directory publication patterns rather than
describing a folder name as an ACL or moving historical studies silently.

`clip.QcRecord` validates fields and an approved-verdict string; it does not verify a
signature. `delivery.promote_candidate` checks MP4 digest, sidecars, renderable editing
plan, optional source identity and actual reconciliation before unchanged-byte publication.
It currently trusts that supplied record's approved string and does not bind/authenticate
every sidecar/edit-plan/configuration through trusted signed review. Its source hashing
reads whole bytes; bounded stream/snapshot identity is needed for the approved large-input
contract. Preserve real measurement/reconciliation while adding the authenticated boundary.
Preference-to-QC export refusal is not a replacement for a working reviewed delivery path.
