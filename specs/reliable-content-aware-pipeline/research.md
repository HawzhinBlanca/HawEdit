# Research — reliable, content-aware HawEdit

Date: 2026-09-06. Scope: research and a proposed implementation plan; no implementation authorization is recorded here.

## Executive read

HawEdit's opportunity is to reduce the correction work required to turn Sorani interviews and podcasts into faithful, watchable clips. Its existing model stack and media pipeline already cover most necessary capabilities; adding models or effects is not the first move. The current source still has gaps between a helper existing, the production path using it, and a delivered artifact proving the intended behavior. Several quality checks measure proxies that are useful diagnostics but cannot establish the claims attached to them. Content awareness should mean preserving the question, qualification, speaker, reaction and payoff that make a moment understandable, then choosing the least intrusive edit that fits that evidence. A defensible top-grade result requires independent holdout review and fault testing, with explicitly limited claims about supported inputs and runtime versions.

Audience: Hawa and Kurdish editors working on source-grounded Sorani social clips. Horizon: the next reliability and quality release, followed by ongoing regression protection. The initial supported domain is Sorani interviews, podcasts and news discussion on the existing Windows/WSL workstation. This is not a plan for a general SaaS editor, social scheduler or universal video understanding system.

## Current-system findings

| ID | Observed source evidence | Consequence / inference | Confidence and next proof |
|---|---|---|---|
| R1 | `measure.py:517` `probe_caption_ink` samples a fixed lower band and uses Laplacian variance; it also derives a percentile-based grayscale ratio. | Background texture can resemble caption ink. This does not prove text identity, correct shaping, glyph coverage or standards-compliant contrast. | High confidence in implementation; false-accept rate unmeasured. Challenge it with uncaptioned textured footage and intentionally corrupted captions. |
| R2 | `reframe.py:362` `MotionSpeakerTracker.track_speakers` assigns the only detected face to the active diarized speaker; multi-face selection uses lower-face pixel changes. | An off-screen speaker plus visible listener can be mislabeled. Camera motion and cut changes can corrupt mouth-motion evidence. | High confidence in branch behavior; prevalence unmeasured. Use annotated listener shots, head turns, pans and overlapping speech. |
| R3 | `delivery.py:333` `reconcile_delivery` checks face presence for `crop_target == "face_tracked"`; the opening-face check additionally requires explicit `min_face_share`. `pipeline.py:2936` does not pass it. Speaker output uses `speaker_face`. | The active-speaker and first-frame claims are not fully covered by this reconciliation path. A detected face is not proof of the correct speaker. | High, source-grounded. Add tests through the actual CLI and final artifact verifier for every supported crop label. |
| R4 | `episode.py:178` `select_episode_plan` and `delivery.py:598` `publish_episode_timeline` have no production callers found in `src/` or `scripts/`. `pipeline.py` uses `max(shippable, key=_shippable_sort_key)`. | Batch selection helpers are not a connected episode-to-deliveries workflow. | High for this scoped search; confirm with Serena before edits. |
| R5 | The episode helper ranks by hook score; the main pipeline ranks with `tournament_score`. Missing transcript falls back to candidate ID for lexical diversity. | Wiring the helper unchanged would introduce policy drift and meaningless semantic diversity when text is absent. | High. Centralize eligibility/ranking; mark lexical similarity as a proxy; require actual content evidence. |
| R6 | `judge.py:846` `compute_repeat_k_agreement` appears in unit tests, not production callers in the scoped search. Rubric anchors and score aggregation exist. | Rubric wording and an agreement helper are not calibration against Kurdish human judgments; repeated model confidence is not accuracy. | High. Use `editorial_acceptance.py` and episode-disjoint human holdout data. |
| R7 | `silence.py:56` proposes removals from gaps between aligned words. A trimmed MP4 needs one consistent mapping for captions, cuts, review markers and edit exports. | High for source behavior; actual drift requires a composed real-media regression. |
| R8 | `pipeline.py:2883` refuses an unreviewed production render, then the delivery error path discards the private bundle. QC binds the reviewed SHA to rendered bytes. | The canonical path needs an explicit retained review candidate and promotion of those exact bytes. Re-rendering to satisfy review is fragile and needlessly expensive. | High for path; operator workaround behavior not audited. Test render → retain → review → promote without render. |
| R9 | `clip.py:666` describes `QcRecord` as signed, but fields are reviewer, date, media hash, watched duration, verdict and notes; there is no signature in that record. | It is an attributed record, not cryptographic proof of identity or that a human watched. Hash binding proves artifact identity only. | High. Correct terminology and enforce an explicit human-only approval boundary using existing project trust conventions. |
| R10 | `durable_workflow.py:10` deliberately wraps the entire invocation in one DBOS step and relies on artifact caches. D-A3 justifies this single-host design; a real process-restart test exists. | Do not replace DBOS/SQLite or split every stage by default. Prove cache reuse and external side-effect behavior at crash boundaries; improve only the missing recovery seams. | High. Existing test does not alone prove recovery of every GPU/cloud/render boundary. |
| R11 | `content_type.py:53` contains fixed podcast/interview/news/social defaults. Rendering uses these alongside presets and explicit options. | A label-specific preset is useful but is not per-shot understanding. Resolve settings once and base changes on actual speaking, scene and semantic evidence. | High. Add precedence and mixed-scene acceptance cases. |
| R12 | Existing source includes measured delivery, two-pass loudness, artifact publication, transcript identity checks, acceptance kits, agent proposal tools and provenance. D-272 retires speculative scale/variant modules. | Reuse and repair these pieces. A second framework or parallel pipeline would increase drift and maintenance burden. | High. ## Opportunity map

- First approved work unit: establish the clean baseline, reproduce R1/R2/R3/R8 with meaningful regression cases, lock the evaluation protocol and preserve review candidates. This is the highest-confidence route to fewer false success claims.
- Following release units: context-grounded selection, one timeline mapping, evidence-based framing and captions, batch integration and bounded recovery. Sequence by the dependency order in `plan.md`, not by a calendar promise.
- Deeper research only after baseline data: per-dialect accuracy, semantic judge calibration, off-screen speaker handling, tolerance calibration and blind preference against competitors and a Kurdish editor. Model replacements require the existing measurement/approval process.

## Research conclusion

Earn the rating by reducing harmful and labor-intensive mistakes on unseen Sorani episodes. The essential loop is source evidence → constrained edit decision → rendered artifact → independent checks → human review → publication of the same bytes. Every claim needs evidence suited to that claim; texture, a score, a passing unit test and an installed model are insufficient substitutes.
