# Acceptance specification — reliable content-aware pipeline

Status: proposed. Approved-by: pending human approval in `plan.md`.

Every test name below is **proposed**, unless separately identified as existing in `impact-map.md`. These tests have not been written or run. Behavioral acceptance requires the real-media and human evidence in `plan.md` in addition to automated checks. No test count or unit-test pass is a proxy for media quality.

| ID | EARS acceptance criterion | Named automated test(s) proposed |
|---|---|---|
| AC-01 | WHEN a final-encode render has no approving human record, THE system SHALL retain an immutable private review candidate, report awaiting review and withhold public delivery. | `test_unreviewed_render_is_retained_privately_for_review` |
| AC-02 | WHEN the owner approves an unchanged candidate, THE system SHALL verify its source, plan, configuration and media identity and promote exactly the reviewed bytes without re-rendering. | `test_approved_candidate_promotes_identical_bytes_without_render` |
| AC-03 | WHEN a reviewed candidate is revised or its dependencies change, THE system SHALL invalidate the prior approval on both canonical and revision paths and require review of the new bytes. | `test_boundary_revision_does_not_rebind_previous_review`, `test_caption_revision_requires_review_of_new_bytes`, `test_candidate_dependency_change_invalidates_approval` |
| AC-04 | WHEN a QC record rejects a clip, has an unsupported verdict or lacks required attribution, THE system SHALL refuse approval and publication through every CLI and revision path. | `test_cli_rejected_qc_record_cannot_authorize_delivery`, `test_unknown_review_verdict_is_refused` |
| AC-05 | WHEN an uncaptioned textured frame is evaluated, THE system SHALL not accept background texture as proof of burned-in captions. | `test_textured_background_cannot_prove_caption_presence` |
| AC-06 | WHEN rendered captions have wrong text, broken joining, missing glyphs, unsafe placement or illegible configured geometry, THE system SHALL fail the corresponding text/shaping/geometry check and preserve explicit unknowns where automatic verification is insufficient. | `test_caption_verification_detects_wrong_text_and_broken_joining`, `test_caption_verification_rejects_missing_glyphs_and_unsafe_geometry` |
| AC-07 | WHEN any supported crop mode claims speaker or subject tracking, THE system SHALL enforce that mode's evidence requirements, including opening-frame checks, without accepting mere face presence as speaker identity. | `test_all_claimed_crop_modes_use_matching_verification`, `test_opening_subject_check_runs_through_default_pipeline` |
| AC-08 | WHEN presets, content type and explicit options are combined, THE system SHALL resolve one effective configuration with documented precedence and reject incompatible inputs before expensive work. | `test_effective_configuration_preserves_explicit_overrides`, `test_incompatible_configuration_refuses_before_model_load` |
| AC-09 | WHEN retained source intervals contain cuts or silence removal, THE system SHALL derive MP4 timing, ASS/SRT cues, EDL/OTIO spans, scene/crop events and review markers from the same source-to-output mapping. | `test_trimmed_render_and_all_sidecars_share_one_time_mapping` |
| AC-10 | WHEN media has VFR or fractional frame rate, THE system SHALL preserve a declared timebase and meet the locked synchronization tolerance without accumulated rounding drift. | `test_vfr_and_fractional_rate_keep_audio_caption_and_edit_alignment` |
| AC-11 | WHEN a candidate removal intersects speech, uncertain alignment, protected breathing/reaction or context-bearing pause, THE system SHALL retain that interval or request review rather than classify the word gap as disposable silence. | `test_silence_policy_preserves_quiet_speech_and_protected_beats` |
| AC-12 | WHEN a candidate requires an earlier question, referent or later qualification, THE system SHALL include the required canonical contiguous context or reject it and record source-linked reasons. | `test_candidate_retains_question_and_qualification_or_refuses` |
| AC-13 | WHEN an editorial proposal cites missing sentence IDs, invents timing or reverses a protected negation/attribution, THE system SHALL reject it before ranking or rendering. | `test_editorial_proposal_rejects_unverifiable_source_references`, `test_high_hook_score_cannot_override_meaning_failure` |
| AC-14 | WHEN both discovery paths run or source content contains instructions to the model, THE system SHALL preserve independent candidate inventories, reject instruction-driven policy changes and account for full source coverage. | `test_discovery_paths_remain_independent_with_full_coverage`, `test_transcript_instructions_cannot_change_policy_or_approve_qc` |
| AC-15 | WHEN single-clip and episode selection evaluate the same candidates, THE system SHALL apply the same eligibility and stable ranking policy and record uncertainty without equating model agreement with human accuracy. | `test_single_and_episode_modes_share_eligibility_and_ranking`, `test_uncertain_judgment_obeys_retry_and_review_budget` |
| AC-16 | WHEN a listener is visible while another person speaks or a shot changes, THE system SHALL avoid unverified speaker attribution, reset invalid spatial state and choose an explicitly labelled acceptable fallback when needed. | `test_visible_listener_is_not_assigned_to_offscreen_speaker`, `test_scene_cut_resets_invalid_speaker_spatial_state` |
| AC-17 | WHEN speaker/layout evidence varies briefly, THE system SHALL avoid camera jitter using the approved persistence policy while allowing a verified sustained turn change. | `test_layout_policy_holds_on_ambiguity_and_switches_on_verified_turn` |
| AC-18 | WHEN rendering an accepted plan, THE system SHALL preserve canonical caption text, use readable shaped geometry and verify final audio against the declared delivery contract without inferring speech quality from loudness alone. | `test_mobile_caption_layout_preserves_canonical_sorani`, `test_final_audio_is_measured_after_conditioning_and_encode` |
| AC-19 | WHEN an episode requests up to N clips, THE system SHALL deliver only distinct eligible candidates using shared preprocessing and record every selected item's actual state without filling the quota with weak clips. | `test_episode_cli_renders_distinct_eligible_clips_with_shared_ingest`, `test_episode_manifest_exposes_partial_failure_and_no_clip_outcome` |
| AC-20 | WHEN a run restarts after interruption at an artifact or publication boundary, THE system SHALL reuse verified completed work, preserve approved bundles and publish each artifact at most once. | `test_restart_at_each_artifact_boundary_preserves_verified_work`, `test_duplicate_submission_cannot_duplicate_public_delivery` |
| AC-21 | WHEN a cloud request outcome is unknown or a retry budget is exhausted, THE system SHALL persist the uncertainty and stop or reconcile under the approved policy instead of silently resubmitting or asserting exactly-once billing. | `test_unknown_billed_outcome_is_not_blindly_retried`, `test_retry_budget_survives_process_restart` |
| AC-22 | WHEN disk, GPU, WSL, network or cache integrity fails, THE system SHALL return a structured actionable failure, release owned resources and withhold invalid public output. | `test_fault_matrix_preserves_failure_reason_and_no_false_delivery` |
| AC-23 | WHEN a source, model, adapter, prompt, font, policy, configuration or relevant runtime dependency changes, THE system SHALL invalidate affected artifacts while preserving unrelated verified work and prior immutable releases. | `test_dependency_change_invalidates_only_dependent_artifacts`, `test_previous_schema_migration_and_release_rollback_preserve_evidence` |
| AC-24 | WHEN acceptance results are reported, THE system SHALL reject episode/speaker leakage, account for refusals and all proposals, report uncertainty and refuse acceptance without the required current evidence. | `test_acceptance_split_has_no_episode_or_speaker_leakage`, `test_scorecard_counts_refusals_and_all_proposed_clips`, `test_acceptance_requires_current_evidence_and_reports_insufficient_sample` |

## Required evidence layers

1. Deterministic tests of policy, identity, mapping and state transitions.
2. Real FFmpeg/media integration on representative source conditions through actual CLI/revision entry points; do not stub the behavior being certified.
3. Independent observation of delivered bytes; intentionally wrong output must fail for the right reason.
4. Human reading/listening and blinded contextual judgments on unseen Sorani episodes. An automated test may validate protocol integrity but cannot replace those judgments.
5. Canonical `bash scripts/verify.sh`, the required real-media checks and hosted required CI at the exact committed SHA. Enforcement edits require the visible marker; the gate alone owns report/count evidence.

Existing golden references must not be adjusted to normalize a defect. If an approved policy intentionally changes appearance, retain the existing invariant tests and add a separately reviewed reference rather than silently replacing the answer.
