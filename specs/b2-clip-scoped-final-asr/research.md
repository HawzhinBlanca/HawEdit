## 1. Problem Statement

`pipeline.run_pipeline` currently runs canonical OmniASR (`omniASR_LLM_7B_v2` / fused v12 + `omniASR_CTC_3B_v2` Viterbi forced alignment) once over the entire episode's Stage 0 speech regions (`src/hawedit/pipeline.py:3089–3139`) before Stage 2 indexing, Stage 3 discovery, Stage 4 judging, and Stage 5 boundary fusion choose which 5–10 clips (`max_clips`) actually ship.

Empirical and historical measurements on `HawaPC01`:
- `evidence/asr-profile-2026-11-18.md`: on the 5-min 4K VP9 excerpt (`zar-ai-lamo__RO1PmSoqmCM__05m00-10m00.mp4`, `300.014 s`), Silero VAD found `61` speech segments (`273,534 ms`), which `_contextual_speech_regions` (`src/hawedit/asr.py:1357`) grouped into `21` context windows (`290,366 ms`); `_cut_speech_regions` (`src/hawedit/asr.py:1410`) took `1.526 s`.
- `evidence/full-sorani-stage1-acceptance-2026-08-10.md`: on `ZAR38MinTest.mp4` (`2,313.8 s`), Stage 1 WSL worker runtime over `547` regions was `2,524.3 s` (`RTF 1.091`); `C:\Users\Wareen\HawEdit-ZAR-ASR-final-verdict-20261008.md` measured `13,288.42 s` (`3.7 h`, under a concurrent test gate).
- `C:\Users\Wareen\Desktop\omniasr-v11-audit\results\hawedit_t0_measure.json`: fused v12 + CTC-3B incurs a `221.1 s` model load plus `RTF ~0.38–0.54` per greedy+CTC forward on RTX 3090 Ti GPU 1.

Running final-pass OmniASR v12 + CTC-3B only on the chosen clips (each padded by `3–5 s`, e.g., ten `45 s` clips = `<= 8 min` of speech vs `60+ min` full episode) cuts Stage 1 ASR audio volume by ~7–10x without giving up v12 caption fidelity or CTC-3B word timings on shipped reels.

## 2. Existing Architecture & Why Naive Slicing Fails Parity

### 2.1 How canonical Stage 1 slices and decodes audio
1. `OmniAsrProducer.transcribe` (`src/hawedit/asr.py:1304–1337`) and `WslOmniAsrProducer.transcribe` (`src/hawedit/asr.py:1875–2013`), when `context_grouping=True` (set unconditionally by `create_omni_asr_producer` at `asr.py:2040,2043,2046,2048`), pass `speech_segments` through `_contextual_speech_regions(speech_segments)` (`asr.py:1357–1383`), merging adjacent Silero VAD segments separated by `<= 1,000 ms` (`_CONTEXT_MAX_GAP_MS`) up to `18,000 ms` (`_CONTEXT_MAX_SPAN_MS`).
2. `_cut_speech_regions` (`asr.py:1410–1458`) extracts one 16 kHz mono WAV per `_ContextSpeechRegion` with `ffmpeg -ss ... -t ...` from `stage0/audio.wav`.
3. Every `speech-XXXX.wav` is decoded independently by `transcribe_prepared_segments` (`asr.py:1500–1539`) and timestamp-offset back by `+ segment.start_ms` inside `_assemble_canonical_transcript` (`asr.py:1542–1580`).
4. **Consequence for parity:** If a clip `[in_ms, out_ms]` is padded to `[in_ms - pad_ms, out_ms + pad_ms]` and passed directly as one raw interval to `_cut_speech_regions`, it cuts mid-utterance and splits/shifts the `_ContextSpeechRegion` boundaries relative to the whole-episode run. That alters Wav2Vec2Llama acoustic context, CTC frame grid alignment, and potentially beam-5 retry triggers (`D-332`).
5. **Exact parity mechanism:** Compute `_contextual_speech_regions(ingested.speech)` on the *complete* Stage 0 `ingested.speech` (arithmetic < `1 ms`), then select the ordered deduplicated subset of episode `_ContextSpeechRegion` items `r` overlapping any padded clip window (`r.end_ms > max(0, clip_in_ms - pad_ms) and r.start_ms < min(duration_ms, clip_out_ms + pad_ms)`), passing those exact `SpeechSegment(r.start_ms, r.end_ms)` intervals (preserving episode bounds!) with `context_grouping` preserved or pre-grouped idempotently so each region WAV is byte-identical to the whole-episode run.
   - Note on quartile coupling (`select_for_validation`): Under validator-on (`len(scores) // 4`), global quartile ranking depends on all episode regions, whereas under B6 (validator off by default), every region's greedy v12 + CTC-3B Viterbi alignment is strictly local to its `_ContextSpeechRegion`.

### 2.2 Two-pass pipeline flow and immutable storage (`D-136`, Kurdish Invariant #1)
- Currently `pipeline._build_and_run` rejects `--transcript` combined with `--omni-asr` (`src/hawedit/pipeline.py:5375`).
- `run_pipeline` runs Stage 1 (`pipeline.py:3089–3246`) -> Stage 2 (`3255`) -> Stage 3 discovery (`3279–3374`) -> Stage 4 judging (`3516–3767`) -> Stage 5 boundary (`3768–3965`) or multi-clip `_run_episode_delivery` (`2598–2790`).
- Wait: if a user runs discovery/selection against a **draft** transcript (either `--transcript <draft.json>` today or a fast draft producer such as B3 once built), and also requests clip-scoped final ASR (`--clip-scoped-asr --omni-asr`):
  - **Model-load batching:** `hawedit_t0_measure.json` shows model load takes `221.1 s`. Calling `asr.transcribe` separately for 10 clips inside `_render_episode_single_clip` (`pipeline.py:2081`) would pay `~37 min` in model loads alone. Instead, `_run_episode_delivery` (`pipeline.py:2646–2691`) knows all `selected_items` upfront after `plan_episode(...)` and MUST run **one batched `canonical_asr.transcribe(...)` call** across the sorted union of overlapping `_ContextSpeechRegion`s for all chosen clips!
  - **Write-once invariance (`TranscriptStore.write_raw`):** `work_dir / "transcripts"` holds the episode draft transcript (`{media_id}.transcript.raw.json`), which is write-once (`transcripts.py:1254`). Clip-scoped final ASR MUST write into an isolated store (e.g., `work_dir / "clip_asr" / "transcripts"` keyed by `media_id` and `reusable_raw(media_id, subset_audio_digest, producer_id, source_sha256, admission_policy=...)`), never overwriting the episode draft!
  - **Word/sentence re-mapping at render:** Draft timings/words may differ slightly from final v12 + CTC-3B words at boundary transitions. Re-running `segment_sentences(final_raw.words, vad_pauses=_pauses_between(ingested))` over the clip-scoped final `RawTranscript`, matching/snapping the clip selection to complete final sentences overlapping the chosen candidate/boundary span, and verifying `fuse_boundary` / `_prepare_selection` / uncaptioned-word checks (`pipeline.py:3910–3965`) preserves Kurdish Invariant #2 (complete sentences, no mid-word cut) and Invariant #5 (`ctc_viterbi` word timings).
  - **`WslOmniAsrProducer` context grouping idempotency:** `_contextual_speech_regions` (`asr.py:1357–1383`) is **not** idempotent if called twice! Calling it a second time on two neighboring subsets originally separated by a 18s-split gap could merge differently if spans were `< 18 s`, OR wait — if a single region already came out of `_contextual_speech_regions(ingested.speech)` (say 12 s) and the *next* region was dropped because it lay outside the padded clip window, remaining gaps stay > 1000 ms except wait: what if region A (0..12 s) and region B (12.2..19 s) were NOT merged in whole-episode because `19 - 0 = 19 s > 18 s`, and both overlap the padded window? If `_contextual_speech_regions` runs *again* inside `WslOmniAsrProducer.transcribe` (`asr.py:1887`), `B` stays unmerged (`19 - 0 > 18 s`), GOOD! What if region A (0..8s), B (8.5..17s), C (17.5..24s): whole-episode merges A+B (0..17s) and leaves C (17.5..24s). Both selected -> `(0..17s)` + `(17.5..24s)` won't merge because `24 - 0 > 18 s`. What if ONLY B would be dropped? Adjacent gap widens. **Wait — corner case!** What if A+B merged (0..17s), C+D merged (17.5..34s): they won't merge (`34 > 18`). Can dropping an intermediate region ever create a *smaller* gap? No, dropping a region ONLY increases gaps! What can *shrink* vs expand? Splitting at `18s` only splits an `M` that already spans `> 18s` with previous region `L`; if `L` AND `M` are both selected, `end(M) - start(L)` is STILL `> 18s`! However, explicitly supporting `context_grouping=False` when handing pre-grouped `_ContextSpeechRegion` slices (or asserting parity cleanly with `context_grouping_policy`) eliminates even theoretical drift in admission policy keys while keeping `admission_policy` consistent with whole-episode (`asr.py:1823–1829`). Keeping `context_grouping=True` on already-grouped regions ACTUALLY preserves the exact same `admission_policy` (`...+context-grouping-v1`), AND because every pair `(L, M)` inside a subset preserves monotonicity and all skipped gaps only grow, let's verify in tests (`test_b2_context_grouping_subset_idempotence`) whether any greedy split edge case can occur: suppose `L=[0..10s]`, `M=[10.5..19s]` (`19-0 > 18s` -> unmerged), then `N=[19.5..27s]` (`27-10.5 = 16.5s <= 18s` -> `M+N` merged to `[10.5..27s]`). `27-0 = 27s > 18s` -> `[L, M+N]` still won't merge! Proof by contradiction: if `L` ended before `X` and `X` was split from `L`, `X.end_ms - L.start_ms > 18000`; any later merged window starting at `X` has `later.end_ms >= X.end_ms`, so `later.end_ms - L.start_ms > 18000` still holds! **Therefore `_contextual_speech_regions` is mathematically idempotent on any subset of its own output!** We will still write an automated property test for this in B2.
